# Three-minute demonstration

## Problem (20 seconds)

An issue can be open, unassigned, and labeled good first issue while a PR already exists. Other suitable contributions have no beginner label. Repository processes differ.

## Discover (35 seconds)

In NitroStudio, run list_issues for issuesprint-demo/demo-repo, with TypeScript and documentation skills and 90 minutes. Leave beginner_only and unassigned_only false.

Point out the fictional data badge, unlabeled issue 106, assigned issue 105, explainable matching, tentative scope, and Availability unchecked. Discovery is a shortlist for inspection.

## Inspect existing work (50 seconds)

Run get_contribution_context for issue 102. Show its open PR, observed change-request review, source links, and inspection timestamp. Expand the review excerpt. Explain that review feedback does not establish correctness or abandonment. The suggested plan helps or reviews the existing work.

## Respect repository process (30 seconds)

Inspect issue 106. Show quoted instructions allowing direct PRs without assignment, alongside the conditional discussion requirement for large changes. Explain that no universal assignment rule is imposed and incomplete guidance stays uncertain.

## Act (30 seconds)

Save a specific, reviewed plan through the connected widget. Show returned Markdown and the recorded strategy and evidence. Explain that saving refreshes the evidence and only writes a local plan; GitHub is unchanged.

## Explain MCP (15 seconds)

The client discovers three tool schemas and coordinates them. The TypeScript service owns GitHub access and storage. The client supplies the language model; direct tool execution does not require an AI chat.
